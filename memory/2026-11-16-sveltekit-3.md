# SvelteKit 3 migration (docs)

## Changes

- Docs run on Kit 3.2.0 with adapter-cloudflare 8.0.2, Vitest 5.1, runed 0.38, Superforms 3.1 and Formsnap 2.1. Root `engines.node` is `>=22.17`.
- Wrangler is 4.149.0 (root devDependency and workspace override). Adapter 8 declares `wrangler ^4.118.0`; with the former 4.107.1 pin both `vite dev` and the wrangler preview crash in workerd (`std::terminate`). The user chose the bump.
- `$lib` is gone: docs code imports `#lib/...` with explicit extensions (`.js` for TS modules, `/index.js` for directories) through `docs/package.json` `imports`. `$content/*` became `#content/*`. Markdown `<script>` blocks use `#lib`; prose and fenced code samples keep `$lib`.
- Pipeline constants moved in lockstep to `#lib`: `REGISTRY_DEPENDENCY` and `UTILS_PATH` in `scripts/registry.ts`, the generated-style rewrite in `scripts/design-styles.ts`, registry aliases in `scripts/build-registry.ts`, and the injected example import in `vite.config.ts`. A mismatch builds cleanly but drops `registryDependencies` or leaks `#lib/registry-styles` into published items.
- `tsconfig.json` extends `$app/tsconfig` with explicit `include`; `App.Platform` was removed. `$app/stores` became `$app/state`, `json()` became `Response.json()`, and the `Handle` type comes from `@sveltejs/kit/hooks`.
- The style select uses `goto(url, { shallow: true, replace: true, state })` from the visible URL (`page.shallow?.url ?? page.url`); mobile navigation ignores shallow navigations in `afterNavigate`.
- `vite.config.ts` keeps `$lib` specifiers out of the dependency scan only. Vite regex-extracts import lines from TS `<script>` text, so the `code-block-demo` sample string reached Kit 3's `module_removed_lib` error, aborted the scan, and split the Svelte runtime in browser tests.

## Consumer impact

- Published registry content changed only where imports were extensionless (plus Prettier re-wrapping those longer imports): `$UI$/button` is now `$UI$/button/index.js` and `$UTILS$` is `$UTILS$.js`. `registryDependencies` and npm dependency ranges match the pre-migration registry.
- `build-registry.ts` passes `overrideDependencies` (`runed@^0.37.1`, `sveltekit-superforms@^2.30.2`, `formsnap@^2.0.1`) because published items still target Kit 2 consumers. In a scratch Kit 2 project, npm fails with `ERESOLVE` on runed 0.38 (optional `@sveltejs/kit ^3` peer); pnpm only warns. superforms 3.1 and formsnap 2.1 install on Kit 2, but superforms 3 is a major upgrade with a `svelte ^5.56.4` peer.
- `lily-svelte registry build` now applies overrides to dependencies carried as peers (formsnap carried the project's superforms 3 range); a patch changeset records it.
- The CLI, schemas, READMEs and docs prose still default to `$lib`. Kit 3 consumer support (`#lib` aliases, no `svelte.config.js`, Kit 3 dependency ranges) is a separate follow-up; drop the overrides then.

## Validation

- `pnpm check`: 0 errors and 0 warnings, including on a clean `.svelte-kit`. The three earlier `data-table-demo` errors disappeared with the duplicate Svelte install.
- Lint: prettier reports only the existing `packages/cli/CHANGELOG.md` and package manifest warnings; ESLint reports the same 43 problems as `main`.
- Vitest browser: 2 passed. Build: 115 prerendered pages. E2E: 18 passed on the wrangler preview (the default 60s `webServer` timeout is shorter than the build; a longer timeout was used locally). A dev smoke test covered the style query, history replacement, navigation, preview routes and the Code tab.
- `wrangler types` rewrites `docs/worker-configuration.d.ts` unformatted on each check or build, so it is in `.prettierignore` and committed as raw wrangler output; checks leave the tree clean.
- Not verified: unit tests on the pre-migration tree, `docs/scripts/tsconfig.json` in an editor, and a real deploy.
